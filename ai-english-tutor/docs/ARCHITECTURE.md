# 架构与关键流程

## 1. 进程划分

| 进程 | 端口 | 职责 |
|---|---|---|
| 主站 `app` | 8765 | 页面、会话编排、对话模型调用、语音识别/合成、报告 |
| 评测 `scorer` | 8010 | 只做一件事：WAV + 参考文本 → 逐词音标与分数 |

分开的原因：评测需要独立的 PyTorch 推理栈，冷启动要加载模型；如果和主站同进程，模型加载会阻塞页面与第一轮对话。两个进程由 `tools/launcher.py` 统一拉起、统一回收，健康检查通过后再打开浏览器。

## 2. 一轮对话的时序

```
学生说话
  │ 音频帧（PCM16 / 16kHz）经 WebSocket 持续上行
  ▼
服务端能量 VAD 判定句尾（静音约 2 秒）→ 提交本轮
  │
  ├─► 识别（云 ASR；未配置时回退浏览器识别结果）
  │      └─► 回推字幕给页面
  │
  ├─► 对话模型（流式）──► 逐句切分 ──► TTS ──► 音频下行
  │
  ├─（并行）语法分析 ──► 左侧栏：分数 / 问题 / 改写
  │
  ├─（并行）发音评测 ──► 右侧栏：逐词分数 / 音标 / 弱音素
  │        └─► 发音教练（独立提示词）──► 口型提示与跟读句
  │
  └─（并行）翻译 ──► 英文气泡下方补中文
```

要点：

- **半双工**：外教开口到最后一字播完，麦克风关闭。学生不会打断外教，外教也不会盖住自己的声音。
- **异步补算**：语法、发音、翻译都在独立任务里跑，任何一个慢都不影响下一句外教开口。
- **流式优先**：对话回复边生成边朗读，首字延迟决定体验，因此关闭模型思考模式。

## 3. 上下文与辅导

每轮把整场对话（学生原句 + 外教回复）按字符预算回放给模型，保证能引用前面出现过的人名、地点、约定。

辅导决策看的是**已完成的评分**，不是当前轮：

| 触发 | 条件（可调常量位于 `app/backend/conversation_ws.py`） | 行为 |
|---|---|---|
| 求助 | 学生说听不懂 / 用中文回答 | 逐句讲解 + 简单英文 + 极简问题 |
| 语法纠正 | 近两轮内语法分低于阈值且有问题 | 一句中文点出问题 + 正确英文 + 推进场景 |
| 语法习惯 | 同类问题连续两轮 | 点明这是反复出现的习惯，并降低下一步难度 |
| 发音带读 | 实词低于阈值；连续两轮偏低则免冷却 | 表扬 + 点名 + 跟读句 + 场景提问 |
| 正向激励 | 连续两轮语法干净且发音高 | 具体表扬 + 更难的追问 |

一轮只命中一种策略，避免"说教堆叠"。

## 4. 评分链路

1. espeak-ng 把参考文本转成 IPA 音素序列；
2. 音素模型对录音做 CTC 解码，得到识别音素序列；
3. 逐词对齐后计算准确度、完整度，结合语速算流利度；
4. 汇总为总分，并记录每个词的分数、音标、弱音素。

虚词与双元音滑音段不进入重读建议：它们的词典音标与真实弱读/连读差异太大，分数低但不代表发音错误。

## 5. 模型切换

`app/backend/llm_provider.py` 保存当前选择（内存 + `app/data/llm_provider.json`），所有文本类调用都经过同一层路由：

- 云端与本地模型共用同一套消息格式；
- 带图片的请求始终留在支持视觉的模型上；
- 本地模型不可用时降级为本地模板回复，课堂不会中断；
- 每次调用都写入 `[llm HH:MM:SS] provider=... model=...`，便于核对实际走的哪条链路。

## 6. 失败与降级

| 故障 | 行为 |
|---|---|
| 对话模型不可用 / 余额不足 | 短时冷却，改用本地模板回复，界面提示 |
| 语音合成不可用 | 回退浏览器 `speechSynthesis` |
| 语音识别不可用 | 回退浏览器识别；再不可用则允许直接打字 |
| 评测服务未就绪 | 侧栏显示"评测中/未评分"，绝不伪造分数 |
| 评测服务崩溃 | 对话继续，仅缺发音分 |
